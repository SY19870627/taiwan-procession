## 1. 原則：守住什麼

| 原則 | 具體做法 |
|---|---|
| 語氣：「慈悲審判」「廟會的熱鬧」 | 隨從鬥嘴是「一個想斬、一個想再問」「一高一矮」「一板一眼 vs 嘴碎」，**不寫成第三章太子那種嗆法**；不碾壓、不嘲笑鬼，嘲笑只對自己人（作者已同意 §3 語氣） |
| 不加新數值 | 不加威名、神威、士氣、香火（決策紀錄 2026-10-26）。「今日陣頭」卡只說明，不改任何數值 |
| 不改玩法與平衡（三章都一樣） | `core/boss.ts`、`core/` 其他規則一行不動；`subdue`（石駒）、`escort`（王船）、`jiao`（蛟）的數值與流程不變。最後一戰**只加互嗆字幕**（作者同意的唯一例外，只是顯示）。`boss.test`、`escort.test`、`jiao.test` 等現有測試全部照過 |
| 第三章不退步 | 第三章已有的互嗆時機、台詞、觸發條件全部不變；過場改成演出，但**台詞一字不改**（測試鎖住）；新掛勾只在「這一章有這個台詞」時才播 |
| 神明不露臉（第一、二章） | 維持「旨意」：演出時用旨意圖＋光圈＋「令」字，神明那一拍不放隨從插話 |
| 有圖用圖、沒圖用暫代 | 畫師的檔名對上就自動換（§5）；沒圖時一律用程式畫的暫代，不會壞 |
| 補寫的字都標【待定】 | 程式裡的補寫台詞／旁白在資料上標 `draft: true` 或註解【待定】，並列進 §9 |

## 2. 實作階段（第 1～7 階段）

每階段都在一次執行內做完；結束前 `npm run build`、`npm test` 全過、工作目錄乾淨，再 commit＋`git push origin feat/ch12-lively`，並在 §10 記一行。

### 共用名詞

- **演出腳本**（stage script）：一段過場的走位、鏡頭、泡泡資料，格式沿用原型 `content/protoStage.ts` 的 `StageScript`（第 1 階段正式化，可能加欄位）。台詞**直接對應 `CUTSCENES[id].lines` 的第幾句（`src`）**，測試核對一字不差；補寫的拍子標 `draft`。
- **演出播放器**：第 1 階段從原型 `ProtoStageScene` 改成通用元件，由 `StoryScene` 呼叫：這段過場有演出腳本就播演出，沒有就播現在的文字版（畫面完全不變）。
- **深層連結**（測試、截圖、作者驗收用）：`?scene=story&id=<過場id>&ch=<章>`；第 1 階段加 `&beat=N`（直接跳到第 N 拍、鏡頭已停好，截圖用）與 `&text=1`（強制播文字版，對照用）。測試區網址形式：`https://sy19870627.github.io/taiwan-procession/test/?scene=story&id=recall&ch=wanjia`。

## 4. 演出方式（已定：引擎內演出）

作者選 **(2) 引擎內演出**（Q6），三章一致（Q7）。比較過的另外兩種：(1) 分鏡插畫（臨場感最高但要 30～60 張圖、手機記憶體風險高）、(3) 剪影（風格和遊戲落差大、第三章已有正式美術會退步），都不採用。

技術要點（原型已驗證）：

- 鏡頭不用 Phaser 相機縮放，而是把整個舞台放在容器裡縮放、平移；泡泡與字幕畫在容器外，位置照鏡頭停下來的地方算，所以字不會變大、永遠在畫面內。
- 全部用已載入的貼圖，不另外下載大圖；效能風險低。
- 台詞直接對應 `CUTSCENES[id].lines`，演出與文字版不會分岔。
