# 兩個遊戲之間，怎麼同步除錯回報核心

正本只放在 dream-cafe 的 `src/debug/core/`。taiwan-procession 的同一份資料夾是複本，不要在複本上改；要改就改正本，再同步過去。兩邊各有單元測試核對 `MANIFEST.json`（檔案少了、多了、內容不同、核心版本不同都會失敗）。

更完整的 API 說明在核心裡面的 `src/debug/core/README.md`，這份只寫兩個 repo 實際怎麼同步。

## 這台電腦上的位置（小葉）

| 角色 | 路徑 | 分支 | 說明 |
| --- | --- | --- | --- |
| 正本 | `D:\Git\dream-cafe\src\debug\core` | `feat/v3b-acts1-4` | 改核心只在這裡改 |
| 複本（除錯分支） | `D:\Git\tp-debug\src\debug\core` | `feat/debug-report` | 從 `feat/ch4-voice-pass` 開出的 worktree |
| 第四章工作區 | `D:\Git\tp-ch4` | `feat/ch4-voice-pass` | 不要把核心寫進來，免得跟第四章的改動混在一起 |
| 正式版 checkout | `D:\Git\taiwan-procession` | `main` | **不要**同步到這裡，也不要在這裡改檔 |

同步時目標請寫 `D:\Git\tp-debug\src\debug\core`（或相對路徑 `../tp-debug/src/debug/core`）。不要寫成 `../taiwan-procession/src/debug/core`，那會進到 main。

## 同步步驟

在 dream-cafe 目錄執行：

1. 改完核心後，先重算正本的 MANIFEST（沒帶目標資料夾，只更新正本）：

   `node scripts/sync-debug-core.mjs`

2. 再複製到遶境的除錯分支：

   `node scripts/sync-debug-core.mjs ../tp-debug/src/debug/core`

   腳本會把整個核心複製過去，兩邊寫一份一樣的 `MANIFEST.json`（每個檔的 sha256、核心版本、來源 commit）。正本已經刪掉的檔，複本也會刪。

3. 兩邊都跑測試，確認 MANIFEST 測試通過：

   - dream-cafe：`npm test`
   - taiwan-procession（在 `D:\Git\tp-debug`）：`npm test`

4. 兩個 repo 分別在自己的分支 commit。不要 force push，不要合併到 main。遶境要上測試區時，先問再推。

改了核心的對外行為，要改 `version.js` 的 `CORE_VERSION`（只改內部：第三碼；新增設定或函式：第二碼；舊用法會壞：第一碼）。dream-cafe 改完核心後記得跑 `npm run debug-core:manifest`（或上面的同步腳本），否則 MANIFEST 測試會失敗。pre-commit 不會自動跑這一步。

## 哪些要一起看、哪些不要同步

- **要同步的只有** `src/debug/core/` 整個資料夾（含 `MANIFEST.json` 與 README）。
- **不要同步** 各遊戲自己的轉接層：dream-cafe 的 `src/debug/ui.js`、`config.js`、`jump.js` 等；taiwan-procession 的 `src/debug/adapter.ts`、`config.ts`、`probe.ts`、`jumps.ts`、`position.ts`、`version.ts`。
- **html2canvas**：核心預設用 1.4.1。dream-cafe 在 `vendor/html2canvas.min.js`，taiwan-procession 在 `public/vendor/html2canvas.min.js`。換版本時兩邊要一起換，檔案內容要一樣。
- **收件端**：兩個遊戲用同一個 Apps Script 網址，靠回報裡的 `game` 欄位區分。設定檔裡的密語不要印出來，也不要寫進核心。
- **測試區建置**：taiwan-procession 的 `.github/workflows/deploy-test.yml` 要帶 `VITE_DEBUG_TOOLS: '1'`；正式版的 `deploy.yml` 不要設這個變數。正式版 dist 不應出現除錯程式。

## 測試區怎麼才看得到

`deploy-test.yml` 目前會在推送這些分支時更新測試區：`feat/ch3-xinying`、`feat/ch12-lively`、`feat/ch4-baishadun`、`feat/ch4-voice-pass`。`feat/debug-report` 還不在清單裡。要讓測試區出現除錯面板，需要先決定其中一種做法，再推送（推之前要再問一次）：

- 把 `feat/debug-report` 加進觸發清單再推這個分支；或
- 把這次改動合併進已經會部署的分支（例如 `feat/ch4-voice-pass`）再推；或
- 推上去之後，在 GitHub 手動跑 `workflow_dispatch`。

測試區網址加上 `?debug=1` 才會出現 DBG 與回報鈕。正式版即使加了參數也不應出現。
